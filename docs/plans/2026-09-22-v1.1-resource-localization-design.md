# FlowNote V1.1 Resource Localization Design

**Date:** 2026-09-22  
**Status:** Approved direction — implementation follows this document  
**Applies to:** V1.1 Visual Library reusable HTML Visuals; Note Format v1 remains frozen

## 1. Product decision

Remote dependencies are **never downloaded automatically**.

FlowNote may detect that a Visual references remote resources and show that state, but network access occurs only after the user explicitly clicks **Make Local** for that Visual. Collect, browse, preview, insert, open, and normal editing do not silently acquire network authority.

This is the selected **Approach A**.

## 2. First-slice scope

The first localization slice supports static dependencies that FlowNote can identify and replace deterministically:

- classic `<script src="https://...">`
- `<link rel="stylesheet" href="https://...">`
- `<img src="https://...">`
- absolute HTTPS `url(...)` references in inline CSS
- relative or absolute CSS `url(...)` references discovered inside a localized stylesheet, resolved against that stylesheet URL

The first slice does **not** claim to localize:

- CSS `@import`
- `<script type="module">` or static/dynamic ES module imports
- runtime `fetch()` / XHR
- Worker / SharedWorker
- runtime WASM loading
- arbitrary URLs assembled by JavaScript
- protocol-relative URLs without an explicit scheme

Unsupported/dynamic cases remain external and are surfaced as unresolved diagnostics when FlowNote can detect them.

## 3. Persistent model

Localization is a mapping, not blind source rewriting.

`index.html` remains the user's Current HTML source and `original.html` remains provenance. Make Local does not rewrite either file solely to replace CDN URLs.

The mapping is stored in the existing, extensible `block.json` under `resources.localized`:

```json
{
  "resources": {
    "localized": [
      {
        "source": "https://cdn.example/app.js",
        "resolvedSource": "https://static.example/v2/app.js",
        "path": "assets/localized/8d3f.../app.js",
        "type": "script",
        "mime": "application/javascript",
        "sha256": "..."
      }
    ],
    "localizationIssues": [
      {
        "source": "https://cdn.example/theme.css",
        "reason": "css-import-not-supported"
      }
    ]
  }
}
```

These are content dependency mappings, not trust or network permissions. They therefore remain compatible with Note Format v1 and the existing rule that runtime network authority cannot be persisted.

## 4. Runtime behavior

The HTML runtime resolver receives the Block config in addition to the private asset reader.

For each supported remote reference:

1. if an exact localized mapping exists, FlowNote reads the mapped managed asset and materializes a runtime data/blob URL;
2. if no mapping exists, the persisted remote URL remains in source but the current sandbox network policy continues to block it by default;
3. for localized stylesheets, CSS `url(...)` references are resolved against the stylesheet's final response URL after redirects (`resolvedSource` when it differs from `source`), matching browser URL-base semantics, and then replaced from their localized mappings.

Runtime URLs never persist back to `index.html` or `block.json`.

## 5. Visual Library ownership

A localized Visual Library item owns its localized payloads under its existing app-owned `assets/**` tree:

```text
visual-library/items/<visual-id>/
├─ visual.json
├─ index.html
├─ original.html
├─ block.json
└─ assets/
   └─ localized/
      └─ <content-id>/
         └─ <payload>
```

Make Local is transactional. FlowNote builds a staged replacement item, downloads and validates all selected supported resources there, writes the mapping, then swaps the staged directory into place. A failed download or validation leaves the previous Library item intact.

## 6. Insert semantics

Insertion keeps value semantics.

The existing Visual Library package already carries `block.json` plus all `assets/**`. When a localized Visual is inserted into a writable Mixed Note:

- a fresh Block UUID is created;
- the mapping is copied into the new Block config;
- localized payloads are copied into that new Block's private `assets/**`;
- the Library item, source Note, and destination Note share no mutable filesystem ownership.

This first slice intentionally uses Block-private localized assets. Note-shared immutable localization (`assets/shared/<resource-id>`) remains the later RES-09/RES-10 architecture step.

## 7. Network and security boundary

Make Local is an explicit privileged action with a narrow downloader:

- HTTPS only in the first slice;
- no cookies, credentials, authentication state, or browser session reuse;
- localhost, loopback, private, link-local, multicast, unspecified, and other non-public IP targets are rejected;
- hostnames are resolved before each request and the validated public address is pinned for that request;
- redirects are followed manually with the same HTTPS/public-address checks on every hop;
- redirect count is bounded;
- per-resource timeout, size, total package size, and resource-count limits are enforced;
- only expected static resource MIME families are accepted for the declared dependency context;
- downloaded bytes stay inert managed files until the existing sandbox/runtime policy decides how they are used.

A Note or Visual cannot grant itself network permission by adding fields to metadata.

## 8. UI

Each Visual card derives a compact state:

- **Remote** — supported remote references exist and none are mapped;
- **Partially Local** — some supported references are mapped, or unresolved dynamic dependencies remain;
- **Local** — all currently detected supported static references are mapped and no known unresolved issue remains;
- no badge — no remote dependency is detected.

For an active, non-Trash item with localizable resources, the card shows **Make Local**. Clicking it is the only download trigger.

Trash items cannot localize. During localization the action is disabled and the normal Library busy/error/notice area reports progress or failure. No download-manager UI is introduced.

## 9. Error semantics

Failures are explicit and non-destructive.

Examples:

- insecure/non-public URL → rejected before download;
- redirect to private host → rejected;
- oversized payload → rejected;
- unexpected MIME → rejected;
- unsupported `@import` / module / dynamic fetch → retained as unresolved, not deleted from source;
- one required supported download fails → the staged transaction is discarded and the prior item remains current.

## 10. Compatibility and non-goals

This slice does not change `formatVersion`.

Older v1-compatible readers that preserve unknown Block config fields can retain localization metadata. Existing Slice 1/2 Visual Library items without `resources.localized` continue to load unchanged.

This slice does not implement session-only “Allow network for this preview” yet; SEC-04/SEC-05 remain planned. It also does not implement Note-shared localization, cross-note shared-resource deduplication, module dependency graphs, dynamic fetch interception, Worker/WASM resolution, or CSS `@import`.
