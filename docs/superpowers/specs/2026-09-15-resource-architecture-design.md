# FlowNote Resource Architecture Design

**Date:** 2026-09-15
**Status:** Approved design / implementation not started from this revision
**Applies to:** Note Format v1, HTML Block runtime, Markdown assets, CDN localization, copy/export/AI resource workflows

## 1. Design rule

FlowNote may implement capabilities in slices, but slices must never redefine or reduce the final product requirement.

The dependency direction is:

```text
PRD / Requirements Matrix
          ↓
Final Product Requirements
          ↓
Note Format
          ↓
Persistent Data Model
          ↓
Resource Architecture
          ↓
Runtime Model
          ↓
Slice Plan
          ↓
Current Implementation Coverage
```

A Slice Plan may say "not implemented in this slice". It must not say or imply "FlowNote will never support this" unless the PRD explicitly removes that requirement.

## 2. Goals

The resource architecture must support, without a future format rewrite:

- Markdown images and attachments
- HTML Block private CSS / JS / images / JSON / SVG / fonts / WASM and other local files
- Multiple independent HTML Blocks in one Note
- Offline-capable localized remote/CDN dependencies
- Runtime-only safe resource URLs
- Session-only network permission
- Deep Copy and cross-note copy
- Browser Bundle export
- Presentation using the same runtime loader
- External editing
- AI HTML edits that add/remove/update resources
- Note movement without path breakage
- Git-friendly, human-readable files

## 3. Ownership model

FlowNote uses three persistent managed resource ownership layers plus remote/runtime states.

### 3.1 Note-managed Markdown resources

Location:

```text
assets/images/
assets/attachments/
```

Owner: the Note.

Used by Markdown content in `content.md`.

Example:

```markdown
![](assets/images/img_0199.png)
```

### 3.2 HTML Block private resources

Location:

```text
blocks/<block-id>/assets/**
```

Owner: exactly one HTML Block.

Typical content:

- custom CSS
- block-specific JS
- images / SVG
- JSON data
- fonts
- WASM
- worker/module files

The persisted HTML may use normal relative web paths:

```html
<link rel="stylesheet" href="./assets/style.css">
<script src="./assets/app.js"></script>
<img src="./assets/chart.png">
```

FlowNote does not create private-resource references from one Block into another Block.

### 3.3 Note-shared localized resources

Location:

```text
assets/shared/<resource-id>/**
```

Owner: the Note. Consumers: one or more HTML Blocks.

Purpose: immutable managed copies of shared/localized dependencies, especially remote/CDN dependencies such as chart libraries, fonts, framework CSS, common runtime libraries, or other resources that should not be duplicated per Block.

Example:

```text
assets/shared/res_0199_echarts/
├─ payload/
│  └─ echarts.min.js
└─ meta.json
```

Shared localized resources are immutable from the normal Block editor. If a user needs to modify one, FlowNote must detach/copy it into Block-private assets or create a new shared resource identity.

This immutability allows same-note copies to share localized dependencies without violating normal HTML Block value semantics.

### 3.4 Remote resources

Remote URL remains external unless localized.

Examples:

```text
https://cdn.jsdelivr.net/...
https://fonts.googleapis.com/...
https://example.com/image.png
```

Remote resources do not gain trust merely because a Note contains their URL.

### 3.5 Runtime resources

Runtime URLs are ephemeral session artifacts generated by the loader/resolver.

Examples may include a Tauri custom protocol, capability URL, blob URL, or another controlled WebView-accessible URL chosen by implementation.

Runtime URLs must never become managed persisted paths.

## 4. Final `.note` resource structure

```text
Timing.note/
│
├─ note.json
├─ content.md
│
├─ blocks/
│  ├─ <block-id-A>/
│  │  ├─ block.json
│  │  ├─ index.html
│  │  ├─ original.html
│  │  └─ assets/
│  │     ├─ custom.css
│  │     ├─ app.js
│  │     ├─ figure.png
│  │     └─ data.json
│  │
│  └─ <block-id-B>/
│     ├─ block.json
│     ├─ index.html
│     ├─ original.html
│     └─ assets/
│        └─ diagram.svg
│
└─ assets/
   ├─ images/
   │  └─ img_0199.png
   ├─ attachments/
   │  └─ report.xlsx
   └─ shared/
      └─ <resource-id>/
         ├─ meta.json
         └─ payload/
            └─ ...
```

`formatVersion` remains 1 as long as older v1 readers can safely preserve unknown fields/directories and newer writers obey the v1 compatibility rules.

## 5. Source vs runtime separation

Persisted source is not the runtime representation.

```text
index.html
+ block.json
+ private assets
+ shared resource mappings
+ session permissions
          ↓
Resource Resolver / Runtime Compiler
          ↓
Runtime HTML + controlled resource URLs
          ↓
Sandbox iframe
```

Rules:

1. `index.html` remains human-readable source.
2. `original.html` remains content provenance source only.
3. Runtime URL materialization never rewrites `index.html` automatically.
4. Runtime network permission is not persisted.
5. Theme adaptation and runtime transformations are projections, not a new content source of truth.

## 6. Resource resolver

The HTML runtime must depend on one logical resource resolver interface rather than ad-hoc regex replacement tied to individual tags.

Conceptual request:

```text
ResourceRequest
├─ note capability
├─ block id
├─ requested URL/path
├─ request type/context
└─ runtime session permission
```

Resolver decisions:

```text
request
  ↓
validate capability and block
  ↓
classify reference
  ├─ Block private relative path
  ├─ Shared localized mapping
  ├─ Remote URL
  └─ invalid / unmanaged local reference
  ↓
apply boundary / traversal / MIME / size / CSP policy
  ↓
return controlled runtime resource or deny
```

The architecture must not expose host absolute paths to the iframe.

Implementation may initially materialize some static dependencies as data/blob URLs, but that is an implementation technique, not the persistent or final architectural contract.

## 7. Remote/CDN localization

Localization is a managed mapping, not blind source rewriting.

Example source remains:

```html
<script src="https://cdn.example/echarts.min.js"></script>
```

A Block may declare a localized mapping in `block.json`:

```json
{
  "resources": {
    "localized": [
      {
        "resourceId": "res_0199_echarts",
        "source": "https://cdn.example/echarts.min.js",
        "type": "script"
      }
    ]
  }
}
```

At runtime:

```text
remote source URL
      ↓
localized mapping exists?
  ├─ yes → load Note shared resource
  └─ no  → require current preview-session network permission or block
```

Benefits:

- Current HTML stays readable
- Original semantics remain clear
- Git diffs stay small
- localization can be removed/rebuilt
- export can materialize resources for browser use

## 8. `block.json` resource role

Private assets do not require an item-by-item manifest because their ownership is implied by `blocks/<id>/assets/**`.

`block.json` may declare dependencies that are not implied by directory ownership, especially shared localized resources.

Compatible extension:

```json
{
  "kind": "html",
  "inputKind": "fragment",
  "scriptPolicy": "sandbox",
  "viewport": {
    "heightPx": 480,
    "width": "wide"
  },
  "resources": {
    "localized": [
      {
        "resourceId": "res_0199_echarts",
        "source": "https://cdn.example/echarts.min.js",
        "type": "script"
      }
    ]
  }
}
```

Missing or unknown resource metadata must default to less privilege, never more privilege.

## 9. Copy semantics

### 9.1 Same-note HTML Block Deep Copy

Normal copy remains value semantics.

Copy creates:

- new Block ID
- copied `block.json`
- copied Current
- copied Original
- independent copy of Block-private `assets/**`

Shared localized resources may remain referenced by both Blocks because they are managed immutable resources.

### 9.2 Cross-note copy

Cross-note copy must carry all required managed dependencies into the destination Note.

Private assets are copied into the new Block.

Referenced shared localized resources are copied/deduplicated into the destination Note and receive destination-valid resource mappings.

FlowNote must not create hidden cross-note filesystem dependencies.

## 10. Markdown asset migration

Ordinary Markdown:

```text
Timing.md
Timing.assets/
```

Mixed Note:

```text
Timing.note/
└─ assets/images/
```

Conversion follows:

```text
Copy
↓
Rewrite candidate managed references
↓
Parse validation
↓
Resource existence validation
↓
Commit new .note
↓
Switch FlowNote current document
```

The source `.md` and old managed assets are not automatically deleted by conversion.

FlowNote rewrites only references it can classify as managed document resources. Absolute paths shown in prose/code and arbitrary external references are not globally rewritten.

## 11. Network permission and trust

Network permission is session-only runtime state.

It is never trusted from `note.json` or `block.json`.

A Note may persist the fact that a remote dependency exists or has a localized mapping; it may not persist "network allowed" or "trusted HTML" as authority.

Network permission expires at minimum when:

- Note closes
- application restarts
- relevant HTML source changes
- preview/runtime session is recreated

## 12. AI resource transactions

Future AI HTML editing must operate on a candidate containing both source changes and resource changes.

Conceptually:

```text
AI Candidate
├─ candidate index.html
└─ Resource Delta
   ├─ add
   ├─ replace
   └─ delete
```

Only user acceptance commits the candidate.

Original remains untouched by ordinary AI Current edits.

This prevents HTML and assets from entering inconsistent partial states.

## 13. Editor / Read / Present / Export reuse

Editor, Read, Presentation and Browser Bundle export must consume the same persistent resource model and shared resolver semantics.

```text
Persistent Note Model
        ↓
Resource Resolver
   ┌────┼─────┐
   ↓    ↓     ↓
 Edit  Read  Present
        ↓
      Export materialization
```

Export may materialize different relative paths, but it must not redefine resource ownership semantics.

## 14. External editing

External editing of managed source files is a valid workflow.

FlowNote should tolerate edits to:

- `content.md`
- `note.json`
- `block.json`
- `index.html`
- `original.html` as a file, subject to provenance validation on save
- Block-private assets

Shared localized resources are FlowNote-managed immutable resources. External mutation is treated as an external resource modification/conflict, not silently accepted as normal Block editing.

## 15. Error handling and security invariants

FlowNote must reject or isolate:

- `..` path traversal
- host absolute managed paths
- cross-Block private resource traversal
- hidden cross-Note dependencies
- symlink escapes from managed directories
- forged Note capabilities
- persisted runtime URLs as managed paths
- automatically persisted network trust

A failure must preserve the user-visible source and leave enough state for recovery. Missing resources should produce diagnostics/placeholders rather than silent source deletion.

## 16. Testing obligations

The final architecture requires dedicated tests for at least:

1. Two HTML Blocks with independent private assets
2. CSS/JS/image/font/JSON relative resources
3. nested CSS `url()` / `@import`
4. dynamic relative `fetch()` / module import when runtime support is introduced
5. traversal/cross-Block rejection
6. moving the whole `.note` directory
7. same-note Deep Copy
8. cross-note copy with shared dependencies
9. Markdown managed image migration
10. remote dependency blocked by default
11. session-only network permission reset
12. localized dependency offline loading
13. Browser Bundle materialization
14. AI candidate source + resource transaction rollback
15. external resource mutation conflict

A slice may implement a subset, but unimplemented obligations remain visible in the Requirements Matrix.

## 17. Current implementation sequencing

Slice 2 should implement a coherent subset of this architecture without redefining it:

- two independent HTML Blocks
- Block-private resources and safe resolver boundary
- real-disk persistence/reopen/move tests
- Markdown managed image migration

The following remain explicit future requirements rather than deleted scope:

- Note-shared localized resources
- CDN localization UI/workflow
- dynamic fetch/import/worker/WASM runtime coverage
- Deep Copy/cross-note dependency transfer
- AI resource transactions
- Browser Bundle resource materialization

These future requirements must stay tracked in `REQUIREMENTS-MATRIX.md`.
